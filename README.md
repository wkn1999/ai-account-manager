# AI账号管家

本机多平台 AI 账号的集中管理器：一键切换登录态、查看额度用量、每日签到领奖励。
所有数据只存在你自己的电脑上，不上传任何内容。

## 功能

- **检测并导入本机账号**：读取各客户端在本机的登录态，首次启动自动导入
- **多账号批量操作**：卡片左上角勾选后可批量签到 / 批量刷新额度 / 批量删除，每条结果逐个回报；客户端原生多 profile 的平台（如 DuMate）一次导入全部账号
- **登录新账号**：ChatGPT / Codex 在应用内走 OAuth 授权；其余平台一键拉起对应客户端，登录成功后自动检测导入
- **一键切号**：把选中账号的登录态写回客户端配置文件，切换前自动留 `.bak` 备份
- **额度看板**：环形用量图、剩余量、资源包到期时间（绝对时间 + 精确倒计时）、分项用量（如「代码补全 29 / 5000」）
- **每日签到**：对支持的平台一键领取免费额度，并展示「今日已签到 / 未签到 / 连续天数」；无签到接口的平台会在卡片上明确标注「无签到活动」
- **异常可见**：登录态失效、签到检测失败、额度获取失败都会在卡片上标红并写明下一步操作，不会静默显示旧数据
- **状态筛选**：待签到、已签到、即将到期（7 天内）、已过期、用量触顶，统计卡片点击即筛选
- **会话管理**：Qoder 会话存于本地数据库，可完整导出 / 导入；Trae 本地只能归档会话索引，切号时可自动保护会话，避免切号丢失会话上下文
- **Trae 自定义智能体**：一键全部归档（免导出文件、免勾选）、导出 / 导入 JSON 包、导出可粘贴清单（完整提示词 / 工具 / MCP，用于在 Trae 客户端内逐个创建）
- **桌面快捷方式管理**：在「工作台 → 快捷方式」中创建 / 更新 / 删除桌面快捷方式，可指定名称与目标 exe
- **定时任务**：定时刷新额度与签到状态，可开启每日到点自动签到
- **搜索**：按名称 / 邮箱 / uid 过滤，左侧按平台分区
- **代理设置**：ChatGPT / Codex 接口直连不通时可显式指定代理，留空则跟随系统代理

## 支持的平台

| 平台 | 检测导入 | 应用内登录 | 一键切号 | 额度查询 | 每日签到 |
| --- | --- | --- | --- | --- | --- |
| Trae 国际版 | 是 | 拉起客户端 | 是 | 是 | — |
| Trae 国内版 | 是 | 拉起客户端 | 是 | 是 | 是 |
| Qoder 国内版 | 是 | 拉起客户端 | 是 | 是 | ✅（sash 双活动，按服务端投放） |
| Qoder 国际版 | 是 | 拉起客户端 | 是 | 是 | 暂未验证 |
| CodeBuddy 国际版 / 国内版 | 是 | 拉起客户端 | 是 | 是 | 国内版支持 |
| DuMate（国内） | 是（原生多 profile） | 拉起客户端 | 是 | 是 | 是 |
| WorkBuddy（国内） | 是 | 否（只读） | 否 | 否 | — |
| ChatGPT / Codex CLI | 是 | OAuth 授权 | 是 | 是 | — |

Qoder 国内版的签到依赖 `Cosy-ClientType:10` 请求头，早期版本误判为无签到接口，v0.3.0 修正；
签到活动由服务端按账号投放（sash 双活动），账号未命中活动时卡片仍会标注「无签到活动」而不是显示一个点了没反应的按钮。
Qoder 国际版暂未验证，卡片同样标注「无签到活动」。

ChatGPT 一栏读取的是 [Codex CLI](https://github.com/openai/codex) 的登录文件 `~/.codex/auth.json`，
用量来自 `chatgpt.com/backend-api/codex/usage`，不涉及网页端 Cookie。

## 使用

从 [Releases](../../releases) 下载：

- `AI-Account-Manager-Setup-<版本>.exe`：安装版
- `AI-Account-Manager-Portable-<版本>.exe`：便携版，双击即用，免安装

窗口右上角「检测本机账号」随时刷新本机登录态；卡片双击名称可重命名。
左侧栏底部点「工作台」打开会话 / 智能体 / 快捷方式三个页签。

## v0.3.3 智能体单个复制提示词

v0.3.2 的「一键全部导入」容易让人以为执行完 Trae 客户端的「智能体」页就会出现这些智能体；实际上 Trae 的自定义智能体列表由云端按账号下发，本机归档只写缓存 / 存档键（切号后可恢复），不会下发到客户端。这不是 bug，是机制决定的。本轮把按钮改名为**「一键全部归档」**，并补上逐个复制能力：

- 工作台 → 智能体，每个智能体行内新增「复制名称」「复制提示词」两个小按钮。复制的是 `listAgents()` 返回的完整 `prompt` 原文（不截断、不 trim、不包 Markdown 代码块），可直接在 Trae「智能体 → 创建」页粘贴；行内预览的 80 字省略号只用于显示，不参与复制。
- 复制先走 `navigator.clipboard.writeText`，在 `file://` 下不可用或被拒绝时自动降级到隐藏 `<textarea>` + `document.execCommand('copy')`；两级都失败会明确报错，绝不谎报成功。整个过程纯前端、不新增 IPC 通道、不写客户端数据库，也不占用全局 busy。
- 成功 / 失败提示走现有 toast：只报名称与字数，**不会把提示词正文打进提示或日志**。
- 页内补充说明：工具与 MCP 配置仍看「导出可粘贴清单」，单个复制只复制名称 / 提示词原文；「本机归档 ≠ 客户端可见」「列表由云端按账号下发」的边界表述保持原样。
- 按钮澄清同步落到按钮文案、取消 / 空列表提示、页内 AGENT_NOTE 与免责说明；本节下方 v0.3.2 章节作为历史记录保留原文，不改写。

原有「导出选中为 JSON / 导入 JSON 包 / 导出可粘贴清单 / 一键全部归档」等功能入口一个未删。

## v0.3.2 智能体一键归档与可粘贴清单

用户反馈「导入的智能体在 Trae 客户端里看不到」。排查结论：本机 `state.vscdb` 里只有
`currentAgentData_<uid>`（当前选中智能体的单值缓存）和本工具自建的 `aam.customAgents.<uid>` 存档键，
**没有任何客户端原生的「自定义智能体列表」键**，`storage.json` / Local Storage / Session Storage 也没有；
该列表由 Trae 云端按账号下发。所以纯本地写库不可能让它出现——这与 Trae 会话正文在云端是同一类限制。

本轮把能力边界讲清楚，并补齐两条真正有用的路径：

- **一键全部导入**：无需先导出 JSON、无需逐个勾选，直接把本机扫描到的全部 custom 智能体一次性归档到
  当前账号的本机缓存与存档键（按每个 Trae 变体自动解析 uid，避免跨变体串账号）。写盘前自动备份原库、
  检测客户端是否关闭；切号后可从存档恢复定义。
- **导出可粘贴清单**：生成一份 Markdown，逐个给出智能体的名称、唯一名、完整提示词、内置工具与 MCP 服务，
  可直接在 Trae 客户端「智能体 → 创建」页逐段复制。这是让智能体真正出现在客户端的稳妥办法。
- **文案纠错**：原「导入会写回 Trae 客户端」易被理解成会出现在客户端列表，已改为明确说明
  「本机归档 ≠ 客户端可见」；确认弹窗、页内提示、主进程 note 与本文档同步修正。
- 原「导出选中为 JSON / 导入 JSON 包」流程完整保留，两条新能力通过 `exportAgents({manifest:true})` 与
  `importAgents({all:true})` 走同一套数据结构，不新增 IPC 通道。

## v0.3.1 界面简洁化

本轮只改渲染层，**没有删除任何功能入口**，把总览从「一堆数字方块 + 一堆筛选 + 满屏小字」收敛成一眼能扫完的三层：

- **总览精简**：7 个统计方块 → 3 个极简数字块（托管账号 / 今日已签到 / 需关注账号）。「待签到 / 7 天内到期 / 含过期资源包 / 用量触顶」不再各占一格，而是合并进「需关注账号」计数；具体维度仍由下方 6 个分段筛选（全部 / 待签到 / 已签到 / 即将到期 / 已过期 / 用量触顶）逐个下钻，筛选 id 与判定逻辑完全不变。内容区不再重复写一遍「总览」标题，只保留一行「分段筛选 + 共 N 个账号」；顶栏副标题也只留上下文，不再把同一批数字重复第三遍。
- **卡片两态**：默认「摘要态」，约 160px 高 —— 头像 + 账号名（含「当前」标记）+ 一行邮箱、一个主额度数字 + 一条细进度条、最多 2 个状态标记（签到状态 + 最严重的一条异常）、一行操作。点「查看 N 个资源包 / 详情」展开后，套餐 / 上次使用 / 抓取时间 / 重置时间 / 全部状态标记 / 环形用量图 / 全部资源包与分项指标 / 全部 4 个操作按钮**原样保留**；摘要态「更多」菜单里的刷新额度 / 签到 / 删除，与展开后的按钮是同一批入口。
- **视觉系统**：移除卡片顶部彩色条，当前账号左侧彩条改淡；头像、侧栏平台圆点收敛为统一淡色；正常态 badge 统一中性灰，只有 warn / danger 才上色；主数字 28px、账号名 15px、次要文字 12px，明显减少 10.5 / 11px 密集小字；加大留白、淡化边框与卡片背景层次，减少盒子套盒子；顶栏只保留「检测本机账号」一个高亮主按钮，其余降为无边框次级按钮。深色主题保持不变。

会话 / 智能体 / 快捷方式、平台适配器、签到与切号逻辑、定时任务均未改动。

## 会话与智能体的边界

- **Qoder 会话**：会话正文存在本机数据库里，可完整导出为会话包，导入时写回同一客户端的会话数据库，切号前可开启「切号时自动保护会话」，避免切换账号后丢失会话上下文。
- **Trae 会话**：会话正文在云端、按账号隔离，本机只有会话索引（标题、消息数、更新时间、摘要）。本工具只能归档 / 导出这份索引；跨账号的真迁移会被服务端拒绝，**不做假迁移**，也不会把索引伪装成「已迁移到新账号」。
- **智能体**：Trae 自定义智能体的定义只在本机打开过并缓存下来时才存在。本工具只能导出本机已缓存的定义（名称、唯一名、提示词、工具、MCP 配置），未缓存的智能体无法导出或跨机搬运。**「导入 / 一键全部归档」只归档到本机缓存键，不会让它们出现在 Trae 客户端的「自定义智能体」列表**（该列表由云端按账号下发）；要让客户端显示，请用「导出可粘贴清单」或智能体行内的「复制名称 / 复制提示词」在 Trae 里逐个创建。写入本机数据库前请先完全关闭 Trae。
- 导入会话包 / 智能体包都会二次确认，成功后回报实际导入数量与跳过数量，失败会写明原因。

## 桌面快捷方式

在侧栏「工作台 → 快捷方式」中查看当前状态（是否存在、名称、目标路径、图标、启动参数），
并可指定名称、目标 exe、图标、启动参数与工作目录，点「创建 / 更新」写入桌面，或点「删除快捷方式」移除。
「用当前程序路径填入」会把表单里的目标与图标填成主进程返回的 `appExe`。

开发时 `appExe` 指向 Electron 可执行文件；打包安装后请重新点「创建 / 更新」，
把目标改为安装目录里的 `AI账号管家.exe`，否则快捷方式仍指向开发环境。

## 数据与安全

- 账号快照存在 `%APPDATA%/AI账号管家/accounts.json`，用 Electron `safeStorage`（Windows 上即 DPAPI）加密后落盘，只有当前 Windows 用户能解密
- 额度查询只向你已经登录的平台官方接口发请求，token 不出本机
- 写回登录态前会生成 `<原文件>.bak`，出问题可直接还原
- 无遥测、无统计、无后台上报

## 开发

```bash
npm install
npm run dev      # 构建渲染层并启动 Electron
npm run dist     # 产出 Windows 安装包
npx electron-builder --win portable   # 产出单文件便携版
node scripts/diag.js --quota          # 只读诊断：列出本机检测到的账号与额度
```

技术栈：Electron 33 + React 18 + Vite 5 + electron-builder；渲染层与主进程通过 `contextBridge` 隔离，
`nodeIntegration` 关闭；CodeBuddy 的登录态存在 SQLite 里，用 `sql.js` 解析。
